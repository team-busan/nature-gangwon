## 프로젝트 소개

**Nature 강원**은 **강원도 자연 관광지에 맞춤형 여행 경로**를 제공하여 사용자의 여행을 **효율적이고 편리하게 지원**하는 서비스입니다.

- 코로나19 이후 자연 속에서의 힐링을 추구하는 여행자들이 증가함에 따라, **강원도의 자연환경을 활용한 여행지 추천** 및 **경로 최적화 기능**을 제공합니다.
- 사용자들은 다른 여행자들이 작성한 **여행 계획 페이지를 참고**하여 더 나은 계획을 세울 수 있습니다.

## 2. 채택한 개발 기술과 브랜치 전략

### React, Tailwind CSS, React-query

- React
  - 컴포넌트화를 통해 추후 유지보수와 재사용성을 고려했습니다.
  - 계획 카드, 여행지 카드 등 중복되어 사용되는 부분이 많아 컴포넌트화를 통해 리소스 절약이 가능했습니다.
- Tailwind CSS
  - jsx 내부에 스타일 코드가 포함되어 있기 때문에 파일을 별도로 관리할 필요가 없습니다.
  - 색상, 간격, 사이즈 등 클래스가 정해져 있어 일관적인 디자인을 할 수 있었습니다.
- React-query
  - React Query는 React Application에서 서버 상태를 불러오고, 캐싱하며, 지속적으로 동기화하고 업데이트하는 작업을 도와주는 라이브러리입니다.
  - 복잡하고 장황한 코드가 필요한 다른 데이터 불러오기 방식과 달리 React Component 내부에서 간단하고 직관적으로 API를 사용할 수 있습니다.
  - 더 나아가 React Query에서 제공하는 캐싱, Window Focus Refetching 등 다양한 기능을 활용하여 API 요청과 관련된 번잡한 작업 없이 "핵심 로직"에 집중할 수 있습니다.

### Recoil

- 최상위 컴포넌트를 만들어 props로 유저 정보를 내려주는 방식의 경우 불필요한 props 전달이 발생합니다. 따라서, 필요한 컴포넌트 내부에서만 상태 값을 가져다 사용하기 위해 상태 관리 라이브러리를 사용하기로 했습니다.
- Redux가 아닌 Recoil을 채택한 이유
  - Recoil은 React만을 위한 라이브러리로, 사용법도 기존의 useState 훅을 사용하는 방식과 유사해 학습비용을 낮출 수 있었습니다.
  - 또한 Redux보다 훨씬 적은 코드라인으로 작동 가능하다는 장점이 있었습니다.
- 로그인과 최초 프로필 설정 시 유저 정보를 atom에 저장하여 필요한 컴포넌트에서 구독하는 방식으로 사용했습니다.

### eslint, prettier

- 정해진 규칙에 따라 자동적으로 코드 스타일을 정리해 코드의 일관성을 유지하고자 했습니다.
- 코드 품질 관리는 eslint에, 코드 포맷팅은 prettier에 일임해 사용했습니다.
- 협업 시 매번 컨벤션을 신경 쓸 필요 없이 빠르게 개발하는 데에 목적을 두었습니다.

### 브랜치 전략

- Git-flow 전략을 기반으로 main, develop 브랜치와 feature 보조 브랜치를 운용했습니다.
- main, develop, Feat 브랜치로 나누어 개발을 하였습니다.
  - **main** 브랜치는 배포 단계에서만 사용하는 브랜치입니다.
  - **develop** 브랜치는 개발 단계에서 git-flow의 master 역할을 하는 브랜치입니다.

## 6. 트러블 슈팅

- 여행 계획 작성 드래그 앤 드롭 이슈
  - 여행 계획 작성 페이지에서 드래그 앤 드롭시 UI가 심각하게 엉키고, 스크롤이 강제로 위로 올라가는 버그가 발생했습니다.
  - 문제의 원인을 파악하기 위해 드래그 앤 드롭을 포함한 여러 단계의 컨테이너에 각기 다른 배경색을 적용해 UI가 엉키는 지점을 시각적으로 확인했습니다.
  - 분석 결과, Droppable과 Draggable 컴포넌트가 반복되는 구조 안에서 제대로 관리되지 않고 있다는 것을 발견했습니다.

```jsx
<Droppable>
    <Draggable>
        <여행 장소 컴포넌트 />
    </Draggable>
</Droppable>

<Droppable>
    <Draggable>
        <여행 장소 컴포넌트 />
    </Draggable>
</Droppable>
```

- 위 코드에서는 각 **Droppable**에 부여할 id가 **고유하지 않고, 반복분에서 인덱스만 사용**되고 있었습니다. 하지만 **id가 String 값**이어야 제대로 동작했었습니다.
- 각 Droppable 컴포넌트의 id를 인덱스 대신 고유한 String 값으로 수정했습니다.
- 예를 들어

```jsx
<Droppable droppableId={`Day-${index}`}>
  <Draggable draggableId={`${index}` + `${index2}`}>
    <여행 장소 컴포넌트 />
  </Draggable>
</Droppable>
```

- 고유한 droppableId와 draggableId를 부여함으로써 드래그 앤 드롭이 정확한 위치로 이동하도록 했습니다.

## 7. 개선 목표

1. UI/UX 디자인 개선

- 기존 디자인에서 발견된 미흡한 부분을 개선하여 사용자 경험을 더욱 향상시키겠습니다. 이를 위해 레이아웃 정리, 색상 조합 최적화, 그리고 접근성 향상 요소를 추가적으로 고려할 예정입니다.

2. 작은 애니메이션 추가

- 사용자 인터페이스를 더욱 인터랙티브하게 만들기 위해 렉이 걸리지 않을 정도의 경량 애니메이션을 추가할 예정입니다. 예를 들어 버튼 클릭, 페이지 전환, 또는 로딩 상태를 나타내는 애니메이션을 구현하여 자연스럽고 직관적인 사용자 경험을 제공합니다.

3. 성능 최적화

- 새로 추가되는 애니메이션과 기능이 프로젝트 성능에 영향을 미치지 않도록 최적화 기술을 적용할 예정입니다. 필요 시 코드 리팩토링 및 불필요한 리소스 사용을 줄이기 위한 분석을 병행합니다.

### 정홍천

이 프로젝트는 저에게 많은 배움을 안겨준 동시에 팀워크의 중요성을 다시 한번 깨닫게 해준 값진 경험이었습니다.

처음에는 프로젝트의 기획부터 개발, 배포까지 전 과정을 수행하는 데 있어 팀원 간의 의사소통이 원활하지 않아 어려움을 겪기도 했습니다. 하지만 프로젝트가 진행될수록 명확한 목표 설정과 역할 분담의 중요성을 깨달았고, 이를 통해 점차 효율적으로 협업할 수 있었습니다.

또한, 개발 과정에서 발생한 크고 작은 문제들을 해결하며 트러블 슈팅 능력이 한층 성장했습니다. 특히, UI/UX 설계에서 사용자 관점을 고려한 디자인의 필요성과, 클라이언트 요구사항을 충족시키기 위해 어떻게 기능을 구현해야 하는지 깊이 이해하게 되었습니다.

이 과정에서 저는 기술적 성장뿐만 아니라 프로젝트 관리와 소통 능력에서도 많은 발전을 이뤘습니다.

기술적으로는 새로운 라이브러리와 프레임워크를 활용해볼 수 있었고, 프로젝트 구조화와 코드 작성 시 클린 코드를 실천하려고 노력했습니다.
관리적으로는 명확한 일정 관리와 팀원들과의 지속적인 피드백을 통해 프로젝트의 방향성을 유지할 수 있었습니다.

이 프로젝트를 통해 한 단계 더 성장한 개발자로서의 자신감을 얻었으며, 앞으로의 프로젝트에서도 이 경험을 바탕으로 더 나은 결과물을 만들어낼 수 있다는 확신이 생겼습니다.
